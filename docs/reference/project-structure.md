## Directory Details

### `src/` - Rust Source Code

**Purpose:** Contains all Rust logic for the traffic simulation engine.

**Key Files:**

- **`lib.rs`** - Main WASM entry point
  - Exports public functions callable from JavaScript
  - Initializes the simulation loop
  - Manages WASM-JavaScript communication via `wasm-bindgen`

- **`car.rs`** - Vehicle behavior and movement
  - `Car` struct definition with position, velocity, and state
  - Movement calculations and path following logic
  - Vehicle-specific properties (speed, size, type)

- **`traffic.rs`** - Traffic rule validation engine
  - Implements "Right-before-Left" priority checking
  - Detects vehicles in scan zones
  - Determines yielding behavior

**Planned Subdirectories:**

- **`rules/`** - Modular traffic rule implementations
  - Abstracts traffic logic into pluggable rule engines
  - Supports both RHT (Right-Hand Traffic) and LHT (Left-Hand Traffic)
  - Enables easy addition of new traffic rules

- **`locales/`** - Internationalization (i18n) support
  - JSON files for UI strings in different languages
  - Supports English, German, Japanese, and more
  - Enables global deployment with localized interfaces

### `static/` - Web UI Assets

**Purpose:** Frontend files for the browser-based simulation viewer.

**Key Files:**

- **`index.html`** - HTML structure and SVG container
  - Defines the SVG viewport for rendering
  - Loads compiled WASM module
  - Contains UI controls and information panels

- **`style.css`** - Styling for roads, vehicles, and UI
  - Road and lane styling
  - Vehicle appearance (colors, shapes)
  - UI component styling (buttons, sliders, dashboards)

### `tests/` - Test Files

**Purpose:** Automated tests for code quality and correctness.

RLSim uses a dual-test structure to ensure code quality
while protecting validation methodologies and test strategies.
See [Closed Tests] for detailed rationale.

#### `tests/public/` - Public Tests

**Purpose:** Tests visible to all contributors for development guidance.

- **`unit/`** - Public unit tests for individual Rust modules
  - Car movement calculations
  - Traffic rule validation
  - Basic edge case handling
  - Helps contributors understand expected behavior

- **`integration/`** - Public integration tests
  - Multi-vehicle scenarios
  - WASM-JavaScript communication
  - Basic end-to-end simulation tests
  - Provides development validation

#### `tests/closed/` - Closed Tests

**Purpose:** Private tests maintained separately for final validation.

- **`unit/`** - Closed unit tests for validation
  - Comprehensive edge case coverage
  - Proprietary validation methodologies
  - Regional traffic rule compliance
  - Ensures robust implementations

- **`integration/`** - Closed integration tests
  - Complex multi-vehicle scenarios
  - Advanced traffic conditions
  - Performance and scalability validation
  - Deadlock resolution verification

**Note:** Closed tests are not visible in the public repository.
They are used during the validation phase to verify code correctness
against hidden criteria before merging to main branch.

- **`simple-intersection.rs`** - Basic two-lane intersection

  - Easy to understand and modify

- **`complex-roundabout.rs`** - Advanced multi-lane scenario
  - Multiple intersection types

### `submodules/` - Git Submodules

**Purpose:** External repositories linked as submodules for modular development.

### `pkg/` - Compiled WASM Output

**Purpose:** Generated by `wasm-pack build --target web`.

**Contents:**

- **`rlsim.wasm`** - Compiled WebAssembly binary
  - Contains all Rust logic compiled to WASM
  - Executed in the browser at near-native speed

- **`rlsim.js`** - JavaScript glue code (auto-generated)
  - Bridges Rust and JavaScript
  - Handles type conversions
  - Manages memory between languages

- **`rlsim_bg.wasm`** - Background WASM module
  - Additional WASM resources
  - Generated by `wasm-bindgen`

- **`package.json`** - NPM package metadata
  - Version information
  - Dependencies
  - Build scripts

**Note:** This directory is generated and should not be manually edited.
Regenerate with `wasm-pack build --target web`.

## Root-Level Files

### Configuration Files

- **`Cargo.toml`** - Rust package manifest
  - Project metadata (name, version, authors)
  - Dependencies (`wasm-bindgen`, `web-sys`, etc.)
  - Build configuration for WASM target

- **`Cargo.lock`** - Locked dependency versions
  - Ensures reproducible builds
  - Auto-generated by Cargo
  - Commit to version control

- **`.gitignore`** - Git ignore rules
  - Excludes build artifacts (target/, pkg/)
  - Ignores IDE files (.idea/, *.iml)
  - Prevents committing generated files

## File Organization Principles

### Separation of Concerns

- `src/` - Logic (Rust)
- `static/` - Presentation (HTML/CSS)
- `docs/` - Knowledge (Documentation)
- `submodules/academy/` - Learning Platform (Interactive education)
- `submodules/tests-closed/` - Validation (Private quality assurance)

### Diátaxis Framework

This project's documentation structure follows the [Diátaxis framework],
a best-practice approach adopted by leading open-source projects
(Django, FastAPI, Kubernetes, Sphinx ...)

The framework organizes documentation into four complementary types:

- **Tutorials** - Learning by doing
- **How-To** - Solving specific problems
- **Reference** - Looking up information
- **Explanation** - Understanding concepts

### Industry Best Practices

This project structure is informed by analysis of top 10 similar open-source projects:

- **Game Engines:** Bevy, Amethyst, Godot
- **Graphics Libraries:** Three.js, Babylon.js
- **Physics & Math:** Rapier, `Nalgebra`
- **WebAssembly:** `Wasm-bindgen`, `Yew`, `Leptos`

Key patterns adopted:

- **Modular architecture** - Pluggable rule engines and localization support
- **Clear separation** - Logic, presentation, and documentation in distinct directories
- **Scalability** - Support for internationalization (RHT/LHT) and extensible features
- **Developer experience** - Comprehensive documentation and clear navigation paths

### Scalability

- Modular rule engine (`src/rules/`)
- Internationalization support (`src/locales/`)
- Extensible documentation structure
